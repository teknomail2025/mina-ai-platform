# Mina companion platform foundation

This directory is the shared Flutter client foundation for Android, Windows, and macOS. It is intentionally not a finished app: no chat UI, camera/microphone capture, push notifications, store publishing, or provider credentials are included.

## Architecture
- One Flutter/Dart client codebase; native host projects are generated by Flutter for Android, Windows, and macOS.
- Mina API base URL is supplied at build time with `--dart-define=MINA_API_BASE=...`; the default points to the existing Mina Worker API.
- Authentication uses the existing `/api/auth/login` and `/api/auth/me` endpoints. Session tokens are stored through the platform secure-storage plugin, never in source code or plain preferences.
- Requests carry a platform identifier. The server remains the authority for authorization and user data.
- The bootstrap step adds the Android internet permission needed for HTTPS API access; camera/microphone/notification permissions are intentionally deferred until those features are implemented.
- No Gemini/provider key is shipped to any client.

## One-command local bootstrap
Install the current stable Flutter SDK and the native toolchain for the target OS.

Linux/macOS:
```sh
cd mobile
sh scripts/bootstrap.sh
```

Windows PowerShell:
```powershell
cd mobile
.\scripts\bootstrap.ps1
```

The script generates the Android, Windows, and macOS host projects, resolves packages, runs static analysis, and runs unit tests.

## Native debug builds
Run on the matching native host:
```sh
flutter build apk --debug
flutter build windows --debug
flutter build macos --debug
```

Windows builds require Windows + Visual Studio C++ desktop workload; macOS builds require macOS + Xcode. Android builds require Android SDK and Java 17 or newer.

## Security and scope
- Keep real secrets only in server-side secret storage. Never add API keys to Dart files or `--dart-define`.
- Use HTTPS for non-local API endpoints.
- Camera, microphone, notification, and file permissions must be requested only when their features are implemented and invoked. This foundation does not request runtime permissions.
- The web application and Worker remain unchanged by this client foundation.
- Native builds are CI validation only; no app-store release or production deployment is performed.
